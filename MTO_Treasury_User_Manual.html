1. Overview

The Revenue System is a desktop application for managing real property tax records, assessments, payment history, official receipt information, delinquency monitoring, compliance reporting, and administrative tools.

The desktop app connects to the central API server. The server stores the official database records. Workstations use the desktop app to search, encode, import, generate reports, and perform cashier workflows.

Main User Roles

RoleTypical Access
AdminAll modules, system tools, user settings, health checks, logs, duplicate cleanup, and import tools.
Treasury StaffProperty search, ledger, reports, dashboards, and allowed cashier functions.
Viewer or EncoderLimited modules based on assigned permissions.
Important Menu items can differ by user account. If a page is missing from the sidebar, the account may not have permission to access that module.

3. Starting the App

  1. Open the folder that contains Treasury.exe.
  2. Confirm that .env, server_config.json, and config.json are in the same folder.
  3. Double-click Treasury.exe.
  4. Wait for the login screen to appear.

Required Files

Revenue System folder
|-- Treasury.exe
|-- .env
|-- server_config.json
|-- config.json
|-- logs

The server_config.json file tells the app where the API server is. A common local server setting looks like this: 

{
  "server_url": "http://localhost:8001"
}

For office network deployment, replace localhost with the server computer's IP address, for example http://192.168.1.15:8001.

6. Property Records

Use Property Records to search and maintain taxpayer property details. A property record usually includes TD number, owner name, payor name, barangay, kind of property, assessed value, tax year, PIN, and related fields.

Search for a Property

  1. Open Property Records from the sidebar.
  2. Type a TD number, PIN, owner name, payor name, or location in the search box.
  3. Review the table results.
  4. Select a row to edit, view details, or open related actions.

Add or Edit a Property

  1. Click Add Property for a new record, or select an existing row and click Edit.
  2. Enter the required details carefully.
  3. Review TD number and owner details before saving.
  4. Click Save.
Duplicate TD Number Protection The system blocks duplicate TD numbers. If saving fails with a duplicate TD number message, search for the existing TD number first before creating another record.

Property Dossier

The dossier view shows a consolidated record for a selected property: master details, payment history, assessment changes, and related record history. Use it when reviewing a taxpayer account before editing or posting corrections.

10. How Computation Works

The app computes tax due using the property's assessed value, the tax year, the tax policy rates for that year, recorded penalties, recorded discounts, and payments already posted to the billing record.

Default Tax Rates

Each tax year can have its own rates in System Settings. If no rate is set for a tax year, the system uses these defaults:

ItemDefault RateMeaning
Basic Tax1.00%Regular real property tax portion.
SEF Tax1.00%Special Education Fund portion.
Penalty2.00% per monthUsed by the automatic payment computation for late payments.

Basic Formula

Basic Tax = Assessed Value x Basic Rate
SEF Tax = Assessed Value x SEF Rate
Total Tax = Basic Tax + SEF Tax
Total Due = Total Tax + Penalty - Discount
Balance = Total Due - Amount Paid

The dashboard treats a property as delinquent when its computed balance is greater than zero.

How the Delinquency Dashboard Gets the Balance

The Delinquency Dashboard reads billing rows from the database. A property may have one billing row per tax year. For each property, the app sums all billing rows and compares them with the payments posted against those rows. 

Property Total Due =
  Sum of (Assessed Value x Basic Rate)
+ Sum of (Assessed Value x SEF Rate)
+ Sum of Penalties
- Sum of Discounts

Property Total Paid =
  Sum of Amount Paid on the property's billing rows

Property Balance =
  Property Total Due - Property Total Paid

If Property Balance > 0, the property appears as delinquent.

How the Compute Payment Button Works

When the app computes a payment from assessed value, tax year, and payment date, it applies the following rules:

Payment DateDiscountPenalty
On or before December 31 before the tax year 20% advance payment discount No penalty
January 1 to March 31 of the tax year 10% prompt payment discount No penalty
After March 31 of the tax year No discount Monthly penalty may apply

For late payments, the system starts counting penalty from February 1 of the tax year. The penalty is based on the total tax, not on the assessed value directly. 

Penalty = Total Tax x Penalty Rate x Number of Months Late

Worked Example

Example property: assessed value is PHP 100,000, tax year is 2026, basic rate is 1%, SEF rate is 1%, and penalty rate is 2% per month.

StepComputationAmount
Basic TaxPHP 100,000 x 1%PHP 1,000.00
SEF TaxPHP 100,000 x 1%PHP 1,000.00
Total TaxBasic + SEFPHP 2,000.00
Prompt DiscountIf paid Jan 1 to Mar 31: PHP 2,000 x 10%- PHP 200.00
Net Due During Prompt PeriodPHP 2,000 - PHP 200PHP 1,800.00

If the same property is paid late and the app counts 4 months late:

StepComputationAmount
Total TaxBasic + SEFPHP 2,000.00
PenaltyPHP 2,000 x 2% x 4 monthsPHP 160.00
Net DuePHP 2,000 + PHP 160PHP 2,160.00

Multi-Year Delinquency

If a property has billing records for several unpaid years, each year is computed separately using that year's assessed value and tax policy. The dashboard then adds the balances together. 

2024 Balance + 2025 Balance + 2026 Balance = Total Delinquent Balance
Why the figures may change after sync or import The app can create missing billing-year records from a property's effectivity year or tax year up to the current year. This is why running a billing sync can make a delinquent balance more complete: it fills missing unpaid years that were not originally imported.
Important Existing billing rows keep their recorded penalty, discount, assessed value, and amount paid. Changing a tax policy affects new computations and reports that resolve rates by tax year, but staff should still review existing records before issuing official computations or notices.

14. Import Wizard

The Import Wizard supports bulk loading for property records, assessment roll records, and payment ledger records. The exact mode depends on where the wizard is opened.

Import Process

  1. Open the correct module: Property Records, Assessment Roll, or Ledger.
  2. Click Import.
  3. Select the spreadsheet file.
  4. Review detected columns and mapping.
  5. Click Validate.
  6. Review warnings, duplicate notes, and failed rows.
  7. Click Commit only after confirming the summary.

Spreadsheet Tips

  • Use consistent column names.
  • Remove completely blank rows.
  • Check TD number formatting before import.
  • Keep one taxpayer/property record per row.
  • Save a backup copy of the spreadsheet before importing.
Duplicate Records The system may skip or reject rows with duplicate TD numbers or conflicting values. Review the import summary before assuming every row was inserted.

Auto-Fix Format Issues

Auto-Fix only attempts safe formatting corrections. It can fix common TD patterns such as missing zeroes or misplaced dashes. It skips records that would create a duplicate TD number.

  1. Run Audit TD Numbers.
  2. If format issues exist, click Auto-Fix Format Issues.
  3. Review the dry-run preview.
  4. Confirm only if the previewed fixed TD numbers are correct.
  5. Run the audit again to confirm remaining issues.

Batch Delete Payments Workflow

  1. Open Batch Delete Payments.
  2. Choose OR Number mode or Payment ID mode.
  3. Paste IDs/numbers or load them from a file.
  4. Click Preview.
  5. Review every row that will be deleted.
  6. Confirm the delete only if the preview is correct.
Payment Cleanup Tip Payment ID mode is safer than OR number mode because it targets exact payment rows. Use OR number mode only when you are certain all matching records should be reviewed for deletion.

16. Portable EXE Updates

The PyInstaller build creates a portable executable named Treasury.exe. If the app code is updated, most workstation updates only require replacing that EXE file.

Update by Replacing the EXE

  1. Close the app on the workstation.
  2. Open the installed or portable app folder.
  3. Replace the old Treasury.exe with the new one.
  4. Keep .env, server_config.json, and config.json in the same folder.
  5. Open the app again and log in.

When to Use the Installer Again

  • Installing on a new workstation.
  • Recreating Start Menu or desktop shortcuts.
  • Deploying changed support files or a new manual.
  • Recovering from a missing app folder.

17. Troubleshooting

ProblemLikely CauseFix
Cannot reach API server Server is not running, wrong IP address, or wrong protocol. Start the API server. Check server_config.json. Use http:// unless HTTPS is configured.
Login fails with network error Desktop app cannot connect to the backend. Confirm server health at http://localhost:8001/health on the server PC.
App says SECRET_KEY is missing .env is missing or not beside the EXE. Copy the correct .env file beside Treasury.exe.
500 Internal Server Error Backend issue, database conflict, duplicate record, or server exception. Check backend terminal/logs. Retry after confirming database and server are running.
Duplicate TD number error A property already exists with the same TD number. Search for that TD number and edit the existing record instead of creating another one.
Import fails Spreadsheet format, duplicate values, bad dates, or missing required fields. Review the import summary. Fix spreadsheet rows and try again.
Icon still shows old background Windows icon cache is showing an old shortcut image. Rename the EXE once, recreate shortcut, or restart Windows Explorer.
Basic Health Check If the server is on the same machine, open a browser and visit http://localhost:8001/health. A healthy server should return an online status.
